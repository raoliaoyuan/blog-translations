# 任务：核对另一个模型撰写的技术博客初稿

你正在为一个内部技术博客系列做事实核对（fact-check）。下面会给你一篇 Markdown 初稿。这是另一个 AI 模型生成的，但读者会以为是人工撰写。我们必须确保每一条事实都能站住脚。

## 你的工作

**对每一个 `[^n]` 脚注**，逐条做以下检查并产出一份 review report：

1. **URL 可访问性**：实际访问 / 搜索这个 URL，是否仍然存在？（被删除 / 404 的标记 ❌）
2. **原文支持**：原文是否真的支持引用方的论点？（用一两句话引出原文相关句，判断 ✅ 支持 / ⚠️ 部分支持 / ❌ 不支持 / ❌ 断章取义）
3. **作者身份**：发言时该作者是否真在引用语境中所述的岗位 / 身份？（标记 ✅ / ❌）
4. **日期 / 数字对齐**：引用的事件、数字、价格是否对应历史正确状态？（标记 ✅ / ❌）

**额外检查**：

5. **隐含事实但未引用**：正文中是否有看起来像事实但没有脚注的句子？列出来。
6. **可能的幻觉**：是否有 URL 看起来像编造的（如域名对但路径明显是假的）？是否有人物名 / 职位 / 事件不存在或张冠李戴？
7. **Tier 标注**：每条引用的 Tier 分级是否合理？

## Review Report 输出格式

```markdown
# Review Report: <被核对文件名>

Reviewer: <Codex|Gemini>
Date: 2026-05-26

## 总体评价
<3-5 句>

## 逐条核对

### [^1] <脚注标题简写>
- URL 可访问：✅
- 原文支持：⚠️ 部分支持。原文说 X，引用方推断为 Y，跨度过大
- 作者身份：✅
- 日期对齐：✅
- 建议：改成"原文说 X，可以推测 Y" 或换源

### [^2] ...

## 未引用但需要源的句子

1. "AWS 内部存在转移定价机制" — 这是文章核心论点之一，但找不到对应脚注
2. ...

## 可能的幻觉

1. ❌ 脚注 [^5] 的 URL `https://aws.amazon.com/...` 实际访问返回 404，疑似编造
2. ...

## Tier 标注问题

1. [^7] 被标为 Tier 1 但实际是 Medium 上的个人博客，应该是 Tier 3 或剔除
2. ...

## 总结建议

- 高优修复项：<列表>
- 中优建议项：<列表>
- 可保留项：<列表>
```

## 限制

- **不要重写原文**。只产出 review report。
- **不要发明源**。如果你认为某句话需要源但你查不到，就说"未找到合规来源"。
- **保持冷静批判**。AI 生成的文本经常有看似合理但实际编造的引用，你的工作就是揪出来。
