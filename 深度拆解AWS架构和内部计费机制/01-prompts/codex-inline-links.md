# 任务：给一篇技术博客的正文加内联超链接（保留脚注）

下面的 Markdown 文章使用脚注 `[^N]` 引用外部来源，文末有「## 参考资料」表给出每条脚注的完整 URL。你的任务是：**在保留所有脚注不变的前提下，给正文中的相关文字加 Markdown 内联超链接 `[anchor text](url)`，让读者可以直接点击跳转**。

## 硬约束

1. **绝对不要修改任何脚注定义** — 文末「## 参考资料」section 原封不动。
2. **绝对不要修改任何脚注引用** — 所有 `[^N]` 标记原位保留。
3. **绝对不要修改任何事实** — 不增删句子，不改数字、人名、日期。只在合适位置加 markdown 链接。
4. **不要改 YAML front matter**（但请把 `author` 字段末尾加上 `→ inline-links by Codex`）。
5. **链接 URL 必须真实可访问**。来源就是脚注里给的 URL。**不要造新 URL，不要修改脚注里的 URL**。
6. **不要 hijack 已有的链接** — 如果正文某处已有 `[xxx](url)`，跳过。

## 加链原则

- **anchor text 选自然短语**：服务名（"Amazon EKS"）、产品名（"Firecracker"）、人名（"Werner Vogels"）、文章名（"Stevey's Google Platforms Rant"）、政策事件（"2020 年 EKS 降价"）等。中文 anchor 3-10 字最好，英文 1-3 词。
- **每条脚注对应的论据，至少有一处内联链** — 给读者一个可点击的入口。但不要在同一段反复加同一个链接。
- **重复出现的同一来源不必每次都加**，第一次出现在该 section 时加足够。
- **保留 anchor text 周围的中文标点和句子结构**，例如「Amazon [EKS](url) 控制平面」而不是把整句改成英文。
- 如果原文中某条脚注对应的"事件 / 数字 / 政策"没有合适 anchor（很短、被多个引用共享），可以省略内联链 — 优先选最自然的位置。

## 输出格式

直接输出完整修改后的 Markdown（YAML + 正文 + 参考资料，**全部三部分都要原样输出**），不要解释性前后文。

## 自检（提交前）

- 文中所有 `[^N]` 标记数 = 原文 `[^N]` 标记数（验证：没有少 / 没有多）
- 文末 `[^N]:` 定义数 = 原文 `[^N]:` 定义数
- 新增的 `[anchor](url)` 链接里的 URL **全部出自脚注**，没有编造
