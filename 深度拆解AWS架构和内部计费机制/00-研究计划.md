# 深度拆解 AWS 架构和内部计费机制 — 研究计划

## 1. 本质问题

> 在一个内部强独立核算、强 P&L 文化的组织里，如何让 PaaS 层的团队有动力做出真正好用的产品，而不是为了自己的账面收入去和 IaaS 团队博弈？

AWS 用 **Attributed Revenue + Transfer Pricing** 把"客户价值链上的协同"翻译成了"内部团队的利益对齐"。本系列要把这套机制拆开，并回答它为什么能在 Amazon 跑通、什么时候会失效、为什么别家学不来。

## 3. 选题骨架 + 必备案例锚点

每个案例必须带可访问的源 URL。每篇至少 8 个独立源，Tier 1（AWS/Amazon 官方）至少占一半。

### 第 1 篇：机制本身

- **开篇案例**：EKS 代客拉起的 EC2 节点 — 外部账单 vs 内部归属（基于本次对话整理的内容）
- **对照案例 1**：Lambda on Firecracker — Marc Brooker 论文 + re:Invent 演讲，说明 Lambda 团队如何"消费"EC2 容量并被 attribute
- **政策事件**：2019 年 EKS 集群费从 $0.20/h 降到 $0.10/h — Werner Vogels / AWS What's New 公告，说明降价底气来自 attributed revenue
- **产品差异**：Fargate-on-EC2 vs Fargate-on-ECS 的 launch type 计费差异 — AWS 官方定价页
- **抵扣行为**：Savings Plans / RI 对 EKS 节点的抵扣机制 — AWS Billing 文档

### 第 2 篇：组织与文化底座

- **Bezos 2002 API Mandate**：Steve Yegge 2011 年 Google+ rant（HN 原帖 archive）— 二手但作者实名、文本完整
- **2-Pizza Team**：Bezos 2018 Forum on Leadership Q&A 视频 + Colin Bryar & Bill Carr《Working Backwards》第 4 章
- **PR-FAQ / Working Backwards**：同上书 + Amazon careers 官方页对 LP 的描述
- **Single-Threaded Leader**：Brad Porter LinkedIn 长文（"Mistakes I made as a STL"）+ Jeff Wilke 在 Recode 访谈
- **14 Leadership Principles 官方页**：amazon.jobs（重点引用 Frugality, Ownership, Customer Obsession, Insist on the Highest Standards）
- **Bezos 2016 "Day 1" 股东信原文**：aboutamazon.com 官方存档
- **DynamoDB 原始论文**（2007 SOSP）作为"团队对自己服务负全责"的早期案例

### 第 3 篇：边界与反思

- **CloudWatch / Data Transfer 计费投诉**：Corey Quinn "Last Week in AWS" 多篇（2019-2023）— 说明机制在边缘服务上的副作用

- **GCP "One Google" 对比**：Steve Yegge 2011 长文中的对比段落 + 其本人后续 podcast 访谈

- **机制失效瞬间**：2017 ECS vs EKS 内部博弈 — The New Stack / The Register 报道
- **DynamoDB 内部依赖**：Werner Vogels 博客对 DynamoDB 架构演进的复盘，作为"高阶服务深度依赖底层"的极端案例

## 5. 信源验证协议

### 分级规则

- **Tier 1 一手**：`aws.amazon.com/blogs`, `aws.amazon.com/architecture`, AWS docs, re:Invent 官方 YouTube, Amazon SEC 10-K/10-Q, Amazon 高管在 Amazon 官方渠道的发言（*Day 1* 股东信、aboutamazon.com）
- **Tier 2 可信二手**：前/现 AWS 员工实名个人博客（Werner Vogels, James Hamilton, Marc Brooker, Brendan Gregg, Brad Porter）、Colin Bryar & Bill Carr《Working Backwards》、Steve Yegge 2011 实名 rant、Acquired podcast 对 Jassy/Vogels 的访谈、The Information / Bloomberg 具名记者深度报道
- **Tier 3 仅作旁证**：Hacker News / Reddit r/aws 可识别身份的 AWS 员工发言、Stack Overflow 上 AWS 工程师署名回答 —— 必须在文中标注「未经 AWS 官方确认」

### 禁止引用

Wikipedia、Medium 上无机构背书的匿名文章、AI 生成的"分析报告"、来源不明的中文搬运稿。

### 引用格式

正文中以脚注或行内角标标注；文末「参考资料」表用统一格式：

```
[Tier N - 标题 - 作者/机构 - 发布日期 - URL]
```

### 核对阶段执行清单（review report 每条必填）

1. URL 当前是否可访问（archive.org 不可作唯一来源，但可作辅助备份）
2. 原文是否真的支持引用方的论点（非断章取义）
3. 作者身份核实：发言时是否真在 AWS / 真在该岗位
4. 日期对齐：引用的事件 / 数字对应当时状态
