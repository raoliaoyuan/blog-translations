# 第一部分　问题重定位

> 内部研究报告 · 草稿 v0.1 · 2026-06-27

## 1.1 从"上下行不对称"到"结算模型不对称"

互联网的商业架构是在"下行流量驱动"的物理前提上长出来的。Web、视频、CDN、家宽 PON、运营商互联结算、公有云出向收费——这套体系的每一层假设，都是"内容方→用户方"是流量主流方向。

AI Agent 类业务把这个前提打掉了。它的网络足迹有三个反直觉特征：

1. **输入 token 数远大于输出 token 数**。本研究在 1,533 个本地 Claude Code 会话日志（48,633 次 API 调用）中实测的总体 input:output **usage token** 比为 **162:1**（参见 [05-empirical/scan-summary.md](../05-empirical/scan-summary.md)），其中 96.1% 的上行 usage token 计入 prompt cache_read。**重要口径限定**：（a）这是 Anthropic API 报告的 usage token 计量，不等于网络字节——字节比需 HTTP body 抓包另算；（b）这是单用户样本，不可作为行业字节比。这一数字高于若干 chatbot 时代的成本模型假设（10:1–30:1），但因口径不同（业界估算多不区分 cache_read），暂留为"待扩样验证"的观察，不下"业界系统性低估"的断言。
2. **上行不是间歇突发，而是持续吞吐**。每一轮工具调用都触发一次包含整段对话历史与工具结果的 POST，配上 SSE 长连接接收输出，形成长时间、稳定速率的上行流。
3. **模型 API 端点物理集中度高**（**L3 推断**）。Anthropic 通过 [AWS Bedrock 多区域部署](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html)（含 us-west-2 / us-east-1 / eu-central-1 等）+ 自营推理服务；OpenAI 主要部署在 Azure，其 direct API 的物理 region 与 ASN 不公开；Google 通过 GCP / Vertex 提供 region 化推理。Bedrock 的"可用区"不等同于物理推理位置——这一物理集中度论断在缺乏自有数据中心的厂商上更可靠，对 Bedrock 类多区域部署应弱化。但总体上推理 region 数量与全球终端用户分布相比仍极少。

这三点合起来，触发的不是"带宽不够"这种容量问题——10 Gbps 链路对一条 Agent 调用是绰绰有余。真正受冲击的是**结算模型**：

| 既有商业模型 | 物理前提 | AI Agent 是否破坏前提 |
|---|---|---|
| 公有云"入向免费、出向收费" | 客户消耗下行内容 | **是**：客户主要在上行 |
| 95th percentile in/out 分开计费 | in 和 out 至少有一个远小于另一个 | **是**：上行可能成为新的主峰 |
| 内容方-用户方 settlement-free peering | 双方 traffic ratio 接近 1:1 | **是**：方向反转 |
| 中国"内容资源在三大运营商间互通"假设 | 内容侧主要是国内 CDN/视频 | **是**：模型 API 物理上压倒性地在境外 |

研究本质上要回答的不是"AI Agent 用了多少带宽"，而是"在 AI Agent 的流量结构下，原有商业结算的钱该怎么收"。

## 1.2 三套被冲击的既有结算体系

由下而上，从物理层结算到零售层定价：

### 1.2.1 国际 BGP 自治域间结算（AS ↔ AS）

互联网的真实物理形态是 ~75,000 个自治域（AS）的 BGP 互联网络（参见 PeeringDB 实时统计）。AS 之间的钱通过三种合约结算：

- **IP Transit**：付费上游中转，按 95th percentile 计费。
- **Settlement-Free Peering**：双方对等无结算，通常要求 traffic ratio 接近 1:1。
- **Paid Peering**：付费对等，介于上述两者之间。

围绕这层结算，过去 20 年发生了 Comcast vs BitTorrent (2007)、Comcast vs Level 3/Netflix (2010)、SK Broadband vs Netflix (2019-2023)、欧盟 BEREC "公平贡献费"咨询 (2023-2024) 等多次危机。每一次都是某种"流量不对称"的物理事实把既有合约的商业假设打穿。

AI Agent 是新一轮潜在危机的种子。

### 1.2.2 公有云带宽零售定价（云 ↔ 客户）

AWS 在 2006 年 S3/EC2 发布时定下的"入向免费、出向阶梯收费"范式（参见 [AWS pricing archives](https://aws.amazon.com/ec2/pricing/on-demand/)），被 GCP、Azure 几乎完全继承。这一范式有三个隐含假设：

1. 客户从云上拉数据出来给终端用户消费（出向是钱）。
2. 客户上传数据进来是为了存放、加工、生成更多下载内容（入向是成本中心，免费换数据沉淀）。
3. 客户的下行流量稳态远大于上行。

AI Agent 类客户（包括把推理服务建在公有云上的中小 AI 公司）是反例：他们的真实流量结构是**大量上行（提示、工具结果、文件） + 少量下行（模型回复）**。在现行定价下，他们在云上几乎是"白嫖入向"，而云厂商按假设损失的本该是出向收入。

但**真正受影响的不是云厂自己——是托管在云上的客户**：当他们调用境外推理 API 时，从客户云出口往外是出向收费，外部 API 回来才是入向免费。Agent 流量正好让客户在出向方向产生意外峰值。

2024 年 EU Data Act 强制下调 egress fee（参见 [European Commission Data Act 实施细则](https://digital-strategy.ec.europa.eu/en/policies/data-act)）已经在松动这个范式。AI Agent 加剧了这种松动的必要性。

### 1.2.3 中国公有云与三大运营商结算（云 ↔ ISP，行政市场混合）

中国互联网结算是世界上独一份的混合体：

- 三大运营商（中国电信 / 中国联通 / 中国移动）之间的互联结算长期受工信部行政指导，"南北互联""骨干直联点"是制度遗产。
- 公有云（阿里、腾讯、华为、字节）作为"内容侧"采购**多线 BGP 接入**，价格远高于单线。**示意量级**（来自公开 IDC 渠道商报价，非官方价目，仅供量级参考）：一线城市机房单线 1Gbps/月 ¥10,000–20,000 区间，多线 BGP 同等规格 ¥40,000–80,000，跨境专线（CN2 GIA / 国际加速）再贵 3–10 倍。准确数据需向运营商集采公告或公有云大客户合约取证。
- **跨境带宽**受国家级出口节点配额限制，是稀缺资源。模型 API 几乎全部在境外，意味着 Agent 流量在中国语境下天然撞到跨境带宽这堵墙。

这与海外"市场对等、运营商互联以经济利益谈判"的结算逻辑完全不同。同一套 AI Agent 流量结构投射到中国语境下，触发的是另一种类型的错配。

## 1.3 AI Agent 流量的最小必要描述

> 证据强度：**已观察事实 + 部分实测**。详细数据见 Part 5。

本节只给后续推理需要的最小事实集合，不深入展开：

1. **上行 token 远大于下行 token**：本研究实测中位数 386:1，p90 24,470:1，总体 162:1（[05-empirical/scan-summary.md](../05-empirical/scan-summary.md)）。
2. **上行主体不是用户新输入，而是 cache_read 计量**：实测 96.1% 上行 usage token 计入 prompt cache_read 字段。Anthropic prompt caching 把这部分计费打到 1/10。**字节层面（L2 文献证据已确证）**：cache_read 仍需客户端完整提交 prompt 供服务端 cumulative prefix hashing 识别（[Anthropic Prompt Caching 文档](https://platform.claude.com/docs/en/docs/build-with-claude/prompt-caching) + [SDK 源码](https://github.com/anthropics/anthropic-sdk-python/blob/main/src/anthropic/resources/messages/messages.py)）。**结论**：prompt caching 优化的是服务端 prefill 与客户面计费，**不削减客户端→服务端 HTTP 字节**。详细证据见 [H6 文献证据](../05-empirical/H6-文献证据.md)。
3. **每轮 API 调用结构**：客户端发起 POST，请求体含完整对话历史 + 工具定义 + 工具结果；服务端通过 SSE 流式返回输出。单一会话表现为多轮 POST 串接 + 持续 SSE 长连接。
4. **多模态输入会放大上行 100×–1000×**：单张截图按 1568×1568 计费约 1568 token，但 base64 编码后的 HTTP 包体可达 200KB–2MB（[Anthropic Vision 文档](https://docs.anthropic.com/en/docs/build-with-claude/vision)）。这是 Computer Use / Browser Use 类 Agent 的关键放大器。
5. **推理 region 物理集中度**（L3 推断）：各厂商的 direct API 物理 region 与 ASN 多不公开；可公开核实的是 Bedrock / Vertex 等多云出口的 region 列表。**对本研究最关键的可公开核实事实**：所有主要推理 region 均**不在中国大陆境内**——这才是构成跨境流量瓶颈的基础。其余厂商内部 region 数量分布是推断，不构成结论依据。

凡涉及"全球 Agent 流量在 BGP 层的真实方向分布"的数据，目前**没有公开数据集可直接挂载**——只能通过前缀归属、DNS、traceroute 和 IXP 公开曲线弱推断。这一限制将在 Part 5B 显式说明，并作为开放问题保留到 Part 7。

## 1.4 三类利益方

报告对每类利益方分别量化，避免"对所有人都不利"的笼统结论：

1. **普通用户与企业终端**
   - 家宽：上行成为体验瓶颈（家宽对称化进度参见 [FCC Measuring Broadband America](https://www.fcc.gov/general/measuring-broadband-america)）
   - 企业：出口带宽采购、出口代理与 NAT 资源被持续吞吐占用
   - 中国语境：跨境 Agent 调用受国际带宽与监管双重约束

2. **公有云服务提供商**
   - 入向免费策略的财务可持续性受到挑战
   - 推理服务商作为"超大客户兼直接竞争对手"
   - 跨境骨干 vs 采购运营商带宽的 build-vs-buy 决策

3. **电信运营商 / ISP / IXP**
   - 下行驱动建网逻辑潜在失效（**假设，待数据验证**）
   - 中国语境：跨境带宽的供需失衡与价格信号
   - 监管层"公平贡献费"提案的最新进展（BEREC、欧盟咨询）

## 1.5 研究范围之外

为聚焦结算问题，本研究**不**深入展开以下议题，但会在相关章节简短承认其存在：

- 模型训练流量（大规模 GPU 集群间的 InfiniBand / RoCE 东西向流量）
- 推理服务内部的 KV cache 迁移、MoE 路由等数据中心内拓扑
- AI Agent 本身的能力边界、安全性、产品设计
- 模型 token 计费的合理性（本研究只关心 token 数对应的字节与结算）
- 推理芯片、GPU 供应链经济学
- 数据隐私、出境合规中**与流量结构无关**的部分
