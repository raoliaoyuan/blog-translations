## 8.1 三条核心结论（含已确证事实与结构性推断）

> 本节标题原稿为"三条已确证结论（L1 + L2）"。经 Codex-B 二审指出"集中度、不可绕开性等仍含 L3-L4 推断"，已修订为更准确的标题。每条结论内部分项注明证据层级。

**结论 1：编码型 Agent 在重度用户场景下的 usage token 结构是上行碾压**

- 本研究单用户实测 48,633 次 Claude Code API 调用：**usage token** 上行 / 下行 = 162 : 1（总体），p50 = 386 : 1，p90 = 24,470 : 1（L1）
- 上行 usage token 中 **96.1% 计入 prompt cache_read 字段**（L1 计费层）。经文献证据法（[H6-文献证据](../05-empirical/H6-文献证据.md)）确证：cache_read 内容**仍需客户端通过 HTTP body 完整提交**，prompt caching **不削减**客户端→服务端字节（L2 已解决，原 H6 假设关闭）
- 上行 usage token 中 96.1% 的 cache_read 部分，**经文献证据法确证**（[H6-文献证据](../05-empirical/H6-文献证据.md)）**仍需客户端通过 HTTP 请求体完整提交**——Anthropic prompt caching 只削减计费与服务端 prefill 计算，**不削减客户端→服务端字节**（L2 已确证）
- 业界公开估算（a16z、SemiAnalysis 等的 10:1–30:1）多面向 chatbot 时代，与本研究 Agent 实测差异显著；但口径不同（业界估算是否区分 cache_read 不明），**不能直接得出"系统性低估 X 倍"**——该论断已从结论降级为开放假设 H5

**结论 2：现有三套结算体系都建立在"下行驱动"假设之上**

- **公有云零售（L2）**：AWS / GCP / Azure / 阿里云 / 腾讯云 / 华为云全部沿用"入向免费 + 出向阶梯计费"范式，前提是客户主要在出向消费
- **国际 BGP（L2）**：Settlement-free peering 的 traffic ratio 阈值假设双方流量平衡；95th percentile 计费的三种 in/out 口径都隐含某个方向占主导
- **中国结算（L2 + L3）**：行政指导下的多线 BGP 采购、跨境带宽配额管制都建立在"内容方→用户方"分发逻辑上

**结论 3：历史上"流量结构反转"曾经触发过结算危机，多以私下商业解决**

- 2007 Comcast vs BitTorrent（FCC 介入，2010 法院撤销）
- 2010 Comcast vs Level 3 / Netflix（私下解决）
- 2014 Cogent vs Verizon 互联拥塞（FCC 调查，最终私下解决）
- 2019–2023 SK Broadband vs Netflix（韩国法院介入，2023 私下合作）
- 2023–2024 欧盟 BEREC 与"公平贡献费"咨询（BEREC 2017 维持"生态可自适应"立场，但欧盟咨询持续）

**关键洞察**：每一次危机都不是单一"上下行不平衡"自动触发监管，而是在"末端 eyeball ISP 不可绕开 + 内容方流量高度集中"两个条件同时成立时才升级。AI Agent 流量**可能**具备这两个特征——推理服务商呈现高度集中（OpenAI / Anthropic / Google AI 占主导），用户 ISP 在大多数市场不可绕开——但当前量级是否已足以让两个条件**同时构成结算冲击点**，本研究**没有结论**：需要 ASN 级实测验证推理服务商集中度的精确份额，以及具体合约层面"是否可绕开"的判定。

## 8.2 三套结算体系的错配类型对照

| 维度 | 公有云零售 | 国际 BGP | 中国结算 |
|---|---|---|---|
| **当前假设** | 客户消费下行 | traffic ratio ≈ 1 | 内容方-用户方分发 |
| **被打破的方式** | 客户主要在上行（推理调用） | 推理 ASN 成为反向接收方 | 模型 API 全在境外，跨境上行集中 |
| **当前是否触发调整** | 否（量级未到拐点） | 否（IXP 公开曲线尚未明确显现） | 部分（"东数西算"已显现政策响应） |
| **可能的调整路径** | "AI 流量专项定价" | peering 重新议价 + 公平贡献费博弈 | 推理算力本地化（**鼓励 / 引导**而非强制） |
| **时间窗口估计** | 数年（L4 推断，依赖增长曲线维持） | 数年（同上） | 已开始，未来几年加速（L4 推断） |

## 8.3 演化路径（推断 + 假设，标 L4）

### 短期（1–2 年）

- 公有云仍维持入向免费，但开始在大客户合约中加入 AI 流量条款（不公开）
- IXP 公开曲线可能首次出现可识别的 AI 信号
- 中国"东数西算"工程加速，国内推理服务商在 region 部署上获得政策倾斜
- 推理服务商继续以"自建跨境骨干"避开运营商结算

### 中期（3–5 年）

- 公有云可能首次推出针对 AI 流量的特殊定价模型——或"AI 调用专项费"，或对入向 AI 流量收费
- BGP 层 peering 重新议价；推理服务商可能成为新一代"超大流量发起方"，触发欧盟"公平贡献费"重启
- 中国监管层可能通过定向跨境带宽配额或牌照层级，把推理算力本地化的"鼓励 / 引导"逐步推到更强约束阶段（具体强度依政策选择而定，不预判"强制"）
- 边缘推理（on-device、edge inference）开始切走部分上行流量

### 长期（5+ 年）

- 行业可能出现新型结算单元：从"流量字节"过渡到"token 计费"或"推理调用计费"
- 客户端缓存上下文协议（client-side cache）若成熟，可削减 96% 上行字节
- 多模态 Agent 的物理形态可能让上行字节在 5 年内再放大 10–100×

## 8.4 对不同角色的可操作建议

### 对个人重度 Agent 用户

- 升级家宽到对称带宽套餐（FTTH PON 同等下，运营商通常可向商务套餐升级解锁上行）
- 多模态 Agent 任务尽量在公司/对称带宽环境运行
- 关注客户端缓存协议演进，未来可能显著降低上行需求

### 对企业架构师 / 网络运维

- **重新评估出口带宽采购**：传统按下行 N Mbps 买的 SD-WAN / 专线，在 100+ Agent 用户团队下可能上行先撞墙
- **测量自有 Agent workload 的 in/out 比例**：用 [scan-sessions.py](../05-empirical/scan-sessions.py) 适配自己的工具栈
- **关注出口代理与 NAT 池容量**：持续吞吐 + 多 SSE 长连接对传统 NAT 资源消耗远高于 SaaS 工作负载
- **跨境企业**：明确知道 AI Agent 跨境上行受 CN2 / 国际加速 / 跨境专线定价层级影响，量化采购决策

### 对采购决策者（CTO / CIO）

- 与云厂商谈判时把"AI 调用流量"明示为独立条款，避免未来定价模型调整时的合约风险
- 跨境推理调用占比高的业务，应在合约期内预留"如果跨境带宽政策收紧"的备份路径
- 关注信通院、工信部对算力网络的政策表述，提前布局可能的本地化要求

### 对政策研究者 / 监管视角

- AI Agent 流量是"下一代公平贡献费"博弈的潜在新前线，但语义可能反转（推理服务商成为接收侧抱怨方）
- 中国语境下，"算力本地化"是比"公平贡献费"更可能的回应路径，监管设计应围绕此展开
- 长期跟踪指标见 [Part 7.4](../07-evidence/07-evidence.md#74-长期跟踪指标清单)

### 对推理服务商

- 自建跨境骨干（参考 Google、Meta）是长期战略；与公有云的合约谈判中应明示 AI 流量结构对网络成本的影响
- 客户端缓存协议（context delta / stateful API）是可以单方面推动的产品举措，可大幅削减客户端上行字节
- Region 部署策略应考虑跨境带宽配额变化的可能性

## 8.6 研究的边界

本研究**不**回答以下问题，留作后续独立研究：

- 模型训练流量的网络结构（与推理服务流量截然不同）
- 数据中心内 GPU 集群东西向流量（InfiniBand / RoCE / NVLink）
- 推理服务商内部 KV cache 迁移、MoE 路由的网络架构
- AI Agent 的应用层经济学（如计费模型、用户付费意愿）
- 推理芯片供应链经济学
- 数据隐私、出境合规中与流量结构无关的部分

## 8.7 一句话总结

**AI Agent 可能正在动摇互联网最底层的商业假设——"内容方→用户方"。三套结算体系（公有云入向免费 / BGP 对等 / 中国行政互联）都建立在这个旧假设上。本研究通过 48,633 次真实 API 调用，在 Anthropic usage token 计量层面观测到 162:1 的上下行不对称（仅限单用户、单工具）。其中 cache_read 字节是否仍走 HTTP body 一题已经过文献证据法 L2 确证（[H6](../05-empirical/H6-文献证据.md)：是）；token→网络字节的编码层放大系数与跨用户、跨厂商分布仍需扩样验证。本研究估算的全球量级（5–50 Tbps 是 L4 推断的情景上界，非实测）尚不足以独立触发结算重写。结算重写的具体拐点不下断言，应通过 [Part 7.4](../07-evidence/07-evidence.md#74-长期跟踪指标清单) 的指标动态跟踪；但研究、监测和制度准备工作应当现在开始。**
