# 第六部分　三类利益方的具体影响

> 内部研究报告 · 草稿 v0.1 · 每节标注证据强度

本部分把前文（Part 1 框架、Part 2 BGP 结算、Part 3 公有云零售、Part 4 中国结构、Part 5 实测）的物理事实与制度结构，**落到具体利益方身上**，给出量级估算与方向判断。每节的格式统一为：

1. 现状基线（已观察）
2. AI Agent 冲击点（已观察 + 推断）
3. 量级估算（按本研究实测推算）
4. 开放问题（标"待数据验证"，留至 Part 7）

## 6.1 普通用户与企业终端

### 6.1.1 现状基线

**家庭宽带的非对称性是历史遗产**：

- ADSL 时代上下行物理就不对称（典型 24Mbps↓ / 1Mbps↑），延续到 DOCSIS、PON。
- 当前主流 PON 接入（GPON / XG-PON）已普遍提供对称千兆，但运营商在零售套餐上往往**仍然限制上行**为下行的 1/2 到 1/5。
- 北美 FCC 历年《Measuring Broadband America》报告（[FCC MBA 数据](https://www.fcc.gov/general/measuring-broadband-america)）记录了上行速率的零售层非对称性。
- 中国国内三大运营商的家宽产品上行普遍限制在 30–100 Mbps 区间，与下行 500–1000 Mbps 形成显著非对称。

**企业出口带宽采购也以下行为主**：

- 中小企业 SD-WAN / 普通专线套餐默认按下行带宽计费。
- 大型企业的多线 BGP 出口和 IPLC 跨境专线虽对称，但价格高、合约保守。

### 6.1.2 AI Agent 冲击点

**家宽侧**（证据强度：已观察 + 推断）：

- 编码型 Agent 每次工具调用都触发数十 KB–数 MB 的上行（含工具结果回传）。一个普通用户使用 Claude Code 半小时编码，本研究实测样本中产生的上行 token 量在 **数百万到上千万**——按 token≈4 字节折算，单次会话上行字节量在 **几十 MB 到几百 MB** 量级。
- 多模态 Agent（Computer Use、截图分析）单次截图上行 200KB–2MB，连续工作时上行速率持续在 1–10 Mbps 区间。
- 在 50/10 Mbps 家宽套餐下，上行 10 Mbps 是**满速运行**，且与家中其他上行任务（视频会议、云同步）直接冲突。

**企业侧**（证据强度：已观察 + 推断）：

- 一个 500 人工程团队，假设其中 100 人每天平均使用编码型 Agent 4 小时——按本研究实测样本量级（单用户单 session 上行 50–500MB），日上行量在 **5–50GB / 用户 / 天** 量级，团队总量 **0.5–5 TB/天**。
- 这一量级在企业出口带宽采购的传统假设下（按下行容量买）属于"不在预期内"的上行流量。
- 与 SaaS（典型企业上行 < 1GB / 用户 / 天）、视频会议（< 5GB / 用户 / 天）相比，Agent 流量上行密度高 5–10 倍。

**跨境侧**（中国语境，证据强度：已观察 + L3）：

- 模型 API 物理推理位置：Anthropic 通过 [Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/models-region-compatibility.html) 已多区域部署（含 us-west-2、us-east-1、eu-central-1、ap-northeast 等），其 direct API 不公开物理 region；OpenAI 主要通过 Azure 部署，direct API 物理 region 不公开；Google 通过 GCP / Vertex 提供 region 化推理。**关键**：从中国大陆的视角看，**无论哪一家的 region 都不在中国大陆境内**——这才是构成跨境流量瓶颈的真正事实，而不是某个具体 region 名称。
- 国内 Agent 用户的跨境调用受 [CN2 / 163 / CMI / CUII](../04-china-structure/04-中国结算结构.md#421-主要骨干网) 等骨干网质量分层影响显著。
- RIPE Atlas、APNIC Labs 公开探针数据可用于实测跨境延迟与丢包（**Codex-A2 待补：探针级数据快照**）。

### 6.1.3 量级估算

按本研究实测 ratio + 当前家宽/企业带宽分布外推：

| 场景 | 单用户日上行量级 | 与传统业务比 | 上行链路瓶颈 |
|---|---|---|---|
| 重度编码型 Agent 用户（4h/天） | 5–50 GB | SaaS 的 5–10× | 家宽 30Mbps 上行 ~80% 占用 |
| Computer Use / 浏览器 Agent 用户 | 10–100 GB | 视频会议的 2–5× | 家宽 100Mbps 上行 ~60% 占用 |
| 中等使用（1h/天，对话+少量工具） | 0.5–5 GB | 与 SaaS 相当 | 不构成瓶颈 |

**关键结论**：对个人用户，AI Agent 可能把家宽上行从"几乎用不到"变成"经常打满"。在视频会议/云同步之外，这**可能成为家宽体验侧少见的、稳态的上行瓶颈场景**——具体冲击程度依用户 Agent 使用密度而定，原稿"1995 年以来第一次反转"的强表述已撤回（缺历史长期数据支撑）。

### 6.1.4 开放问题（待数据验证）

- 跨用户、跨 Agent 类型的真实分布（本研究仅单用户）
- 上行限速套餐对 Agent 实际体验的影响测量
- 企业出口代理与 NAT 池在高上行密度下的崩溃阈值

## 6.2 公有云服务提供商

### 6.2.1 现状基线

**入向免费 + 出向阶梯定价**（参见 Part 3 详细数据）：

- AWS / GCP / Azure / 阿里云 / 腾讯云 / 华为云全部沿用此范式。
- 入向免费的商业逻辑：换取数据沉淀，套牢客户，再通过出向收回成本。
- 推理服务商（OpenAI / Anthropic / 国内大模型公司）作为公有云的**超大客户**，传统上是为下行（用户访问、CDN）付出的代表。

**推理服务商的双重身份**：

- 客户：买公有云的 GPU、网络、存储
- 竞争对手：在 AI 应用层与公有云自有产品（Bedrock、Vertex、阿里通义 API）直接竞争

### 6.2.2 AI Agent 冲击点

**对公有云的财务结构**（证据强度：推断 + 待验证）：

- 公有云的出向收入主要来自 CDN-like 客户（直接面向用户分发内容的应用）。AI Agent 客户的核心流量结构是 **从云上调推理 API**：
  - 调用方：客户应用 → 公有云出向（**计费**）
  - 接收方：推理服务（本身可能也是公有云客户）→ 公有云入向（免费）
- 同一笔流量在云生态内部从"出向收入"变为"出向→入向的内部循环"，但只有出向一段收钱。
- 真实净收入是否下降，取决于公有云客户混合中"AI Agent 类"占比的提升速度。

**推理服务商作为大客户的议价权**（证据强度：已观察）：

- OpenAI 与微软 Azure 的关系包含巨额预付费、专属容量、跨数据中心专线。
- Anthropic 与 AWS / GCP 都有大额合作（公开报道 Anthropic 从 AWS 与 Google 各获约 40 亿美元投资 + 算力承诺）。
- 推理服务商在大客户合约层面已经在重塑公有云收费模型，但这一部分**不公开**。

**跨境骨干 build-vs-buy**（证据强度：已观察）：

- Google、Meta 等已经自建全球海缆和骨干（参见 [Submarine Cable Map](https://www.submarinecablemap.com/)）。
- 中国公有云在牌照与跨境管制约束下，难以复制——必须从运营商采购跨境专线。
- AI Agent 的跨境上行流量进一步放大这种 build-vs-buy 决策的差距。

### 6.2.3 量级估算

按当前公开信息粗略估算（**全部为 L4 推断**，待 Part 7 数据校验）：

- 全球 Agent 应用每日 input token 上行总量（基于公开 API 调用量公开估算）：**10^14 ~ 10^15 token/天**
- 字节折算受 [5A.4 节口径说明](../05-empirical/5A-本地实测.md#5a4-从-token-比换算到字节比l4-推断未实测) 约束（token≈字节是未实测假设）；**示意量级**：**40–400 TB/天**，对应平均带宽 **4–40 Gbps**
- 公有云对此部分流量的入向计费收入：**接近 0**（按 inbound free 政策）

**注意**：上述数字与 [6.3.3 节](#633-量级估算) 全球终端用户上行总量（50–500 PB/天）相差约 1000 倍。差异来源是两段估算的**计算路径不同**：本节从全球 input token 总量自顶向下推；6.3.3 节从单用户日上行 × 用户数自底向上推。**两段路径都使用了 L4 假设，差异本身就是当前估算误差带的宽度**。建议读者把这两个数当作"误差带的两端"，而不是任何一个的精确估计。

如果 Agent 流量在未来 2–3 年再增长 10×，入向流量量级可能达到 400–4000 Gbps（按本节口径）——届时**入向免费**的财务可持续性**可能**首次受到真正挑战。所有时间表述均为 L4 推断。

### 6.2.4 开放问题（待数据验证）

- 公有云的 AI workload 收入实际构成（出向 vs GPU vs 存储 vs API 转售）
- 跨云推理调用的真实占比
- 公有云会否推出"AI 流量专项定价"（如对推理 API 调用单独计费）

## 6.3 电信运营商 / ISP / IXP

### 6.3.1 现状基线

**下行驱动的建网逻辑**：

- 过去 20 年骨干扩容的主要驱动是视频流（Netflix、YouTube、TikTok）。
- 接入网升级（FTTH、5G）也以下行为主。
- IXP 的运营经济学建立在 traffic ratio 接近 1:1 的对等假设上。
- 详细历史与 95th percentile 计费细节参见 Part 2 资料笔记 ([codex-a-research-notes.md](../02-bgp-settlement/codex-a-research-notes.md))。

**IXP 与对等结算的现状（截至 2025）**：

- PeeringDB 注册的 IXP 数量超过 1000 个（参见 [PeeringDB Statistics](https://www.peeringdb.com/page/about/)）
- 大型 IXP（DE-CIX Frankfurt、AMS-IX、LINX、HKIX、Equinix Ashburn）的峰值流量已经突破 30 Tbps
- 主要内容方（Google、Meta、Netflix）通过嵌入式 CDN（Google GGC、Netflix Open Connect、Meta FNA）部署到 ISP 网络内，绕开 IXP

### 6.3.2 AI Agent 冲击点

**对 IXP 的方向性影响**（证据强度：推断 + 待验证）：

- 传统 IXP 的流量曲线呈现明显的"晚高峰下行"形态（人们晚上看视频）。
- 如果 AI Agent 流量足够大，IXP 可能出现"工作时间段上行峰"——AI Agent 上行流向少数推理服务商 ASN（OpenAI / Anthropic / Google）。
- 此假设可由 DE-CIX / AMS-IX 的公开 ASN 级流量曲线**未来**验证。**目前公开数据集尚未明确显示此信号**（Codex-A 笔记中详述）。

**对 ISP 商业谈判的影响**（证据强度：推断）：

- 如果 IXP 流量结构反转，**内容方-用户方角色互换**：推理服务商成为"接收方"（接收 prompt 上行），用户 ISP 成为"发送方"。
- 在 settlement-free peering 的 traffic ratio 阈值下，这可能让长期签约的对等关系变得 ratio 越界。
- 历史上 traffic ratio 越界导致的危机：Comcast vs Level 3（2010）、SK Broadband vs Netflix（2019–2023）（详见 Part 2）。

**对监管层"公平贡献费"博弈的影响**（证据强度：已观察）：

- 欧盟 BEREC 2023–2024 咨询的核心论点是"少数大流量发起方（Netflix、Google、Meta）应分担 ISP 网络成本"。
- 如果 AI Agent 流量结构反转方向，**论点的发起方**可能从 ISP 变成推理服务商：推理服务商成为接收侧，反过来抱怨 ISP "向我推送了大量上行流量"。
- 这种语义反转可能让现有"公平贡献费"叙事失效，监管层面需重构。

**对中国运营商的独特影响**（证据强度：已观察）：

- 三大运营商**同时是云厂**（移动云、天翼云、联通云）。在 AI Agent 时代，他们既是网络方又是模型 API 服务方，**利益方角色重叠**与海外完全不同。**量级参考**（来自 [Part 4.5.3](../04-china-structure/04-中国结算结构.md#453-三大运营商上市公司年报)）：中国移动 2024 年报披露移动云收入 RMB 100.4B（同比 +20.4%）、行业云 RMB 83.8B、国际业务 RMB 22.8B、**国际传输带宽 164 Tbps、330 POP** — 此 164 Tbps 已接近 [Part 2.4.2](../02-bgp-settlement/02-bgp-settlement.md#242-跨洋容量层海缆) 中单一主要海缆（2Africa 180 Tbps、MAREA 200 Tbps）的容量量级，构成中国运营商在 AI 跨境流量上的**独有结构优势**。天翼云、联通云相关数据待补。
- 这种重叠在 AI 算力侧的政策回应（"东数西算"、"算力网络"）已经显现：把推理算力本地化是国家战略，而**运营商既是网络供给方又是算力供给方**，可独家受益。

### 6.3.3 量级估算

按 Part 5A 的实测比例外推：

- 若全球 Agent 用户平均每人每天上传 5–50 GB，假设全球重度 Agent 用户 1000 万人，**每日上行总量 50–500 PB**，对应平均带宽 **5–50 Tbps**。
- **原稿"占全球互联网 0.3%–3%"论断撤回**：经 Codex-B 审稿指出，本研究自估的 PB/天 数字（基于 token 比 ≈ 字节比的 L4 假设）与"全球互联网总带宽 1500 Tbps"不在同一口径下——前者是 input token 上行估算，后者是全网双向带宽峰值或平均——直除得出的占比不构成有效比较。
- 替代表述：本研究**没有**可信的"AI Agent 流量占全球互联网"分数。可信的方向性判断是：当前量级**尚不足以**让任何主流 IXP 或 transit 关系出现可识别的方向异常；但增长曲线陡，几年内可能改变这一情况——具体年份不下断言。

### 6.3.4 开放问题（待数据验证）

- DE-CIX、AMS-IX 等 IXP 是否已在公开数据中出现 AI 流量信号
- 推理服务商 ASN 的对等关系变化（**注**：具体 ASN 需通过 DNS / traceroute / RPKI / PeeringDB 对推理 API 域名实测得出。原稿曾给"OpenAI AS54321"等数字，经 Codex-B 审稿核实无据已删除；正确的 ASN 列表需后续实测建立）
- 中国运营商云业务的 AI 推理收入占比

## 6.4 三类利益方影响汇总

| 利益方 | 主要影响 | 量级 | 当前是否触发结算调整 |
|---|---|---|---|
| 个人用户 | 家宽上行从"用不到"变"经常满载" | 单用户日上行 5–50 GB | 否（用户承担体验下降） |
| 企业终端 | 出口带宽采购模型需重估 | 团队日上行 0.5–5 TB | 部分（企业开始升级出口） |
| 公有云 | 入向免费 vs 大客户议价 | 内部循环流量增加 | 否（但拐点临近） |
| ISP / IXP | traffic ratio 与 peering 关系 | 当前量级不足以让主流 IXP 出现可识别异常（具体百分比口径混乱，撤回） | 否（量级不足） |
| 推理服务商 | 自建跨境骨干 vs 采购 | 极大 capex | 部分（Google、Meta 已建） |
| 中国三大运营商 | 既是网络方又是云方 | 难以单独量化 | 是（东数西算政策已显现） |

**核心判断（L4 推断，情景表述）**：**当前 AI Agent 流量的真实量级缺乏可靠的全球公开数据**——本研究自底向上推算的 5–50 Tbps 是情景上界（假设全球 1000 万重度用户 × 5–50 GB/天，且 token≈字节），与 6.2.3 节自顶向下的 4–40 Gbps 估算相差三个数量级。**两端估算都属 L4 推断，不能视为"当前量级"**。可信的方向性结论是：当前量级**尚不足以**独立触发任何结算体系的重写。**如果**未来增长曲线维持高斜率，冲击点会在数年内显现——具体年份不下断言，需配合实测跟踪指标动态判断（见 [Part 7.4](../07-evidence/07-evidence.md#74-长期跟踪指标清单)）。
