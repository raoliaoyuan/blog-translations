# 第五部分 B 节　公开观测与假设区

> 内部研究报告 · 草稿 v0.1
>
> 本节把 [5A 节单用户实测](5A-本地实测.md) 的发现放到公开观测的语境中，明确哪些公开数据集**已经**显示出 AI 信号、哪些**尚未**显示、哪些**几乎不可能**显示。最后一节（5C）把研究 5 个待验证开放假设（H1–H5）固化下来。

## 5B.1 公开观测的三层证据强度

公开观测数据按"距离 AI Agent 字节的远近"分三层：

| 层级 | 数据源 | 与 AI Agent 流量的距离 | 信号强度 |
|---|---|---|---|
| **L1 直接** | 实测 LLM API HTTP body | 直接 | 强（仅本研究 Part 5A 持有，单用户低样本） |
| **L2 间接** | Cloudflare Radar AI bot、DPI 厂商 LLM 分类、IXP 公开曲线 | 间接（看到是 web crawler / DPI 指纹 / 总带宽） | 弱—中 |
| **L3 推断** | RouteViews / RIPE RIS / CAIDA AS Rank 中推理服务商 ASN 动态 | 推断（需先建立 ASN 映射） | 弱 |

**关键校正**：公开观测多停留在 L2/L3，**没有任何公开来源**给出过"全球 LLM API 调用的 HTTP body 字节"实测数据。这就是为什么 Part 5A 的单用户实测（虽然样本量低）仍然是当前对 AI Agent 流量结构的最强证据。

## 5B.2 Cloudflare Radar / AI bot 流量

**口径关键限定**：Cloudflare Radar 公开的 "AI crawler / verified bot" 类别统计的是**网页爬虫**——GPTBot、ClaudeBot、Google-Extended 等——它们在 web 上抓内容用于模型训练 / RAG。这**不是** LLM API 调用本身的字节流。混淆这两类是审稿 Codex-B 明确指出的错误（Round 1 #C.3）。

### 5B.2.1 可挂载数据

【L2】**Cloudflare 2024-07-03 blog**（[link](https://blog.cloudflare.com/declaring-your-aindependence-block-ai-bots-scrapers-and-crawlers-with-a-single-click/)）按访问 Cloudflare 站点覆盖率给出：

| AI Bot | 覆盖率 |
|---|---|
| Bytespider（字节） | 40.40% |
| GPTBot（OpenAI） | 35.46% |
| ClaudeBot（Anthropic） | 11.17% |
| ImagesiftBot | 8.75% |
| ChatGPT-User | 1.84% |
| Claude-Web | 0.04% |
| PerplexityBot | 0.01% |

【L2】**2024-06**：Cloudflare top 1M 站点中 **38.73% 被 AI bots 访问**，只有 2.98% 阻断或挑战（同上 blog）。

【L2】**Cloudflare 2025 Top Internet Trends**（二级报道，[TechRadar](https://www.techradar.com/pro/security/cloudflare-report-reveals-global-internet-internet-traffic-grew-19-percent-in-2025-but-a-lot-of-it-was-just-bots)）：

- AI bots 平均占 HTML requests **4.2%**
- Googlebot 单独占 4.5%
- 非 AI bots 约占 HTML page requests 一半

【L2】**2025-08-04 案例**：Cloudflare 移除 Perplexity verified bot 身份，理由是观察到其修改 user-agent、变更来源 ASN、忽略 robots.txt（[blog](https://blog.cloudflare.com/perplexity-is-using-stealth-undeclared-crawlers-to-evade-website-no-crawl-directives/)）——侧面证明 AI 厂商在主动**规避**公开观测识别，对 H1 的能见度有进一步负面影响。

【L2】**Radar 实时入口**：[Cloudflare Radar Bots](https://radar.cloudflare.com/bots#verified-bots) — verified bots 视图按 7 天 HTTP requests 统计，可作长期跟踪。

### 5B.2.2 对 H1（BGP 方向反转）的有限信号

AI crawler 流量本质上是**用户 ISP → AI 厂商**方向（爬虫从厂商发出，从 web 拉取内容回到厂商），方向上**与 LLM API prompt 上传相同**。但量级与模式不同：

- AI crawler：bursty，按 robots.txt 节流，几乎不持续吞吐
- LLM API：每个用户每个会话都触发，持续吞吐

因此 Cloudflare AI bot 数据可作为 H1 的**弱方向性证据**，但**不构成结构性证明**。

**AMS-IX 上下行对称性**：daily peak in/out 13.308/13.281 Tb/s **几乎完美对称**（差异 0.2%），yearly avg in/out 9.219/9.250 同样接近 1:1——**当前公开数据看不到 AI Agent 上行驱动的非对称信号**。这一观察对 H1 假设构成弱反证：要么 AI Agent 流量量级远未达 IXP 可识别程度，要么它根本没走 IXP（走 hyperscaler 私有 PNI）。

### 5B.3.2 对 H1 的能见度

IXP 公开统计**几乎不可能**在当前阶段识别 AI 推理流量信号，原因：

1. 推理服务商主要走自有骨干（Google、Meta）或公有云出口（Anthropic-Bedrock、OpenAI-Azure），**不走 IXP**
2. 即使经过 IXP，IXP 公开统计粒度是"总带宽 / peer 数 / 端口数"，**不分应用**
3. 看不到 prompt content，没有方法识别 LLM 流量与其他 HTTPS 流量

**结论**：把"IXP 出现可识别 AI 信号"作为 H1 的验证条件**几乎不可能在公开层面实现**——更可能的途径是 ISP 内部 DPI 数据，但**不公开**。

## 5B.4 DPI 厂商年报

[Sandvine](https://www.sandvine.com/global-internet-phenomena-report)（现 Nokia 旗下）的 Global Internet Phenomena Report 是少数能在应用层识别 AI 流量的公开来源。

【L4 未找到】Codex-A4 本轮**未找到**可公开读取的 Sandvine 2024 / 2025 报告中关于 AI / LLM / Generative 流量占比的具体披露。Nokia / Deepfield 在公开报道中强调 AI 网络压力，但属于调研性叙事，不是 DPI 占比数据（[TechRadar 报道](https://www.techradar.com/pro/ai-is-too-big-for-the-european-internet-so-its-time-for-companies-to-work-together-nokia-says)）。

【L3 行业共识】DPI 厂商能识别 AI 流量的途径：

- **DNS / SNI**：域名识别（claude.ai、api.openai.com、generativelanguage.googleapis.com）
- **TLS / QUIC 指纹**：客户端库特征
- **证书 / IP / ASN** 维度
- **流量形态**：flow duration、上下行字节、包长序列、长 POST + SSE 长连接的组合特征
- **限制**：HTTPS 明文 prompt/output **不可见**

**对 H1 的能见度**：Sandvine / Nokia Deepfield **理论上**是当前可获得的最高质量公开 AI 流量信号，但**截至本研究时点没有具体可挂载占比**。

| [RIPE Atlas](https://atlas.ripe.net/) | 主动 ping/traceroute/DNS | 可对 AI API 域名做延迟丢包探测 | 未找到 AI 推理流量 dashboard |

## 5B.6 推理服务商 ASN 映射（L3 推断）

### 5B.6.1 实测方法

可建立推理服务商 ASN 映射的方法：

1. **DNS 解析**：`dig +short api.anthropic.com / api.openai.com / generativelanguage.googleapis.com` → IP
2. **WHOIS / RDAP**：查询 IP → 所属 ASN
3. **traceroute**：路径上的 AS 跳点
4. **[RouteViews](http://www.routeviews.org/) / [RIPE RIS](https://ris.ripe.net/)** ：实时 BGP 路由表，可查 IP 前缀 → ASN
5. **[PeeringDB](https://www.peeringdb.com/)** ：ASN 的 peering 政策、IXP 接入点
6. **[CAIDA AS Rank](https://asrank.caida.org/)** ：ASN 全球互联度排名

### 5B.6.2 本研究的实测局限

本研究**未建立**这一映射。原因：

- 推理 API 普遍走多 ASN 部署（AWS Bedrock 走 AWS ASN、Azure 走 MS ASN、Cloudflare 路由）
- 同一 API 域名可能解析到多个 IP / ASN
- ASN 实测需要一段时间的连续采样
- 与 ASN 关联的"实际推理量"无法从公开数据反推

留为 H1 验证的可行路径，但承认这一路径的工程难度。

## 5B.7 学术研究中的公开数据

【L2】**[arXiv:2504.10688](https://arxiv.org/abs/2504.10688)《Introducing Large Language Models as the Next Challenging Internet Traffic Source》**：远程 user-agent 交互的 proof-of-concept 测量，**平均每 prompt query+response = 7,593 bytes**。这是迄今为止公开学术文献中**最直接**的字节级测量，但是远程交互场景而非生产 API usage 比例。

【L2】**[arXiv:2510.11269](https://arxiv.org/abs/2510.11269)《From Prompts to Packets》**：采集 ChatGPT / Copilot / Gemini Android app 文本与图像生成流量，含 60 小时泛化数据集 + 受控数据集，观察 TLS 1.3 / QUIC / SNI 与上下行模式。**最接近网络层 LLM app 测量**，但是 mobile app 不是 Claude Code 类 Agent 工具循环。

【L2】**[arXiv:2509.06515](https://arxiv.org/abs/2509.06515)《Five Blind Men and the Internet》**：用 472 个 IXP 公开统计研究 2023-2024 总流量，覆盖约 **300 Tbps 日峰值**，估计两年增长 **49.2%**、年化 **24.5%**。这是全球 IXP 流量增长的**最强**基准数据，但不含 AI 应用分类——AI 流量增长**在这 49.2% 两年总增长中是否占主导**完全不可分辨。

【L4 未找到】**2024-2026 公开论文未找到可直接对标 Part 5A 的真实生产 input:output usage token 数据集**。这一空白本身是 H5 假设保留的根本原因——业界估算的 10:1–30:1 既无原始数据也无口径，本研究的 162:1 是当前**唯一可挂载**的 Agent workload 实测。

【L2】H6 相关：[arXiv:2601.06007](https://arxiv.org/abs/2601.06007)《Don't Break the Cache》评估 OpenAI/Anthropic/Google prompt caching，500+ agent sessions 测 cost 与 TTFT，**未测字节**——这一空白被本研究 [H6 文献证据法](H6-文献证据.md) 用文档与 SDK 源码替代。

## 5B.8 公开观测的总结

把所有可挂载的公开观测合在一起，对研究主要假设的支撑能力：

| 假设 | 公开观测能否支撑 | 主要数据源 | 局限 |
|---|---|---|---|
| H1 BGP 流量方向反转 | 弱 | Cloudflare AI bot（口径错位）、Sandvine DPI、ASN 实测 | 公开数据多在 web crawler 层而非 LLM API |
| H2 公有云入向免费拐点 | 极弱 | 云厂价目历史变化 | 拐点信号不在零售价目而在大客户合约 |
| H3 95th percentile 失真 | 不能 | 无公开来源 | 需要 ISP 内部链路监控 |
| H4 中国监管路径 | 中 | 工信部公告、信通院白皮书、运营商年报 | 监管意图不直接显现于数据，多通过白皮书表述 |
| H5 业界估算适用性 | 弱 | a16z、SemiAnalysis 等公开估算 | 业界估算未公开口径 |

**关键洞察**：公开观测能为 H1–H5 提供的支撑都是**有限的**。这正是为什么本研究 Part 5A 的单用户低样本实测仍然在当前阶段是**最强**的可挂载证据——虽然样本小，但**直接**测量 LLM API usage token，没有口径错位问题。

## 5C 节　开放假设区（与 Part 7 同步）

> 本节是 Part 7.3 假设清单在 Part 5 语境下的本地化呈现，方便读者在阅读 Part 5 实测后直接看到所有"尚未确证、待数据验证"的论断。

### H1：BGP 层流量方向反转

> 当 AI Agent 流量足够大时，全球 IXP 与对等链路上将出现"用户 ISP → 推理服务商"方向占主导的流量结构反转。

**当前数据状态**：弱信号。Cloudflare AI bot 是方向相同但模式不同；Sandvine 报告需要 Codex-A4 进一步抓取；IXP 公开统计不分应用。

**验证路径**：[Part 7.3 H1](../07-evidence/07-evidence.md#假设-h1bgp-层流量方向反转)。

### H2：公有云入向免费可持续性拐点

> 当 AI Agent 类客户在公有云总流量中占比超过某阈值，入向免费策略将面临财务调整。

**当前数据状态**：拐点信号不在零售价目，而在大客户合约——本研究无法获取。

**验证路径**：[Part 7.3 H2](../07-evidence/07-evidence.md#假设-h2公有云入向免费可持续性拐点)。

### H3：95th percentile 在 AI workload 下失真

> AI Agent 流量的"持续吞吐 + 上下行不对称"特征会让 95th percentile 计费在某些链路上产生显著失真。

**当前数据状态**：无公开来源。需要 ISP 内部监控数据。

**验证路径**：[Part 7.3 H3](../07-evidence/07-evidence.md#假设-h395th-percentile-计费在-ai-workload-下失真)。

### H4：中国监管路径偏向"算力本地化"

> 在 AI Agent 跨境上行流量持续增长的压力下，中国监管层更可能通过"东数西算""算力网络"等工程，鼓励并引导推理算力境内部署。

**当前数据状态**：中等。工信部 / 信通院 / 三大运营商公告与年报可作部分支撑；具体监管意图需通过持续观察。

**验证路径**：[Part 7.3 H4](../07-evidence/07-evidence.md#假设-h4中国监管路径偏向算力本地化)。

### H5：业界 10:1–30:1 估算是否仍适用于 Agent workload

> a16z、SemiAnalysis 等公开估算的 input:output 比例（10:1–30:1）多来自 chatbot 时代假设，可能不适用于 Agent workload。

**当前数据状态**：本研究单用户 162:1 实测与业界估算差异显著，但口径不明无法直接对比。

**验证路径**：[Part 7.3 H5](../07-evidence/07-evidence.md#假设-h5业界-10130-估算是否仍适用于-agent-workload)。

### H6：Anthropic prompt caching 是否削减字节 — **已 L2 解决**

> 经[文献证据法](H6-文献证据.md) 确证：情景 A 成立——cache_read 仍需客户端完整提交，prompt caching 不削减客户端→服务端字节。

## 5B.9 本部分小结

- 公开观测对 H1–H5 的支撑都是**有限的**——多数停留在 L2 间接或 L3 推断
- Cloudflare AI bot ≠ LLM API 字节，是 Codex-B 审稿明确指出的关键口径错位
- AMS-IX **2026 daily peak in/out 13.308/13.281 Tb/s 几乎完美对称**（差异 0.2%）——构成 H1 的弱反证：要么 AI 量级远未到 IXP 可识别程度，要么走 hyperscaler 私有 PNI
- IXP 公开统计**几乎不可能**在当前阶段识别 LLM API 字节信号
- DPI 厂商（Sandvine / Nokia Deepfield）理论上是**最强**的公开 AI 流量信号来源，但**截至本研究无具体可挂载占比数字**
- 学术论文已开始测 ChatGPT/Gemini 等 app 的字节（[arXiv:2510.11269](https://arxiv.org/abs/2510.11269)），但**尚未给出 Agent workload 的生产 input:output 比例**
- 本研究 Part 5A 单用户低样本实测，虽然样本小，但**直接**测 LLM API usage token，无口径错位
- 真正的扩样验证需要：(a) 跨用户的 SDK instrumentation；(b) 企业出口代理 HTTPS termination；(c) ISP 内部 DPI / NetFlow 数据

**Part 5B 综合论断**（可作为引用）：

> 公开观测目前只能证明"AI 相关自动化访问正在进入 Web 与网络观测面"，**不能**证明"LLM API 推理字节已经导致 BGP 层流量方向反转"。Cloudflare 的强信号是 crawler 不是 API；IXP 的强信号是总吞吐增长不是应用分类；DPI 是最可能识别 AI 应用的公开来源但本研究未找到 2024-2025 可引用占比；学术论文开始测 ChatGPT/Gemini 等 app 的 packets 但尚未给出 Agent workload 的生产 input:output 比例。**因此 H1 当前状态为：公开层面只有弱方向性证据，尚无可确证 BGP 流量方向反转的数据；Part 5A 的 162:1 是直接 usage-token 证据，但仍需 HTTP 字节抓包与 ASN/路径采样才能升级为网络层结论。**

**仍缺数据**（Codex-A4 已抓大部分，剩余以下未找到）：

- Cloudflare Radar AI bots 动态图 API 当前数值（Bot Traffic 页是 7-day 视图，需 API 调用）
- Sandvine / Nokia Deepfield 2024-2025 报告中 AI / LLM 具体占比数字
- LINX / DE-CIX 机器可读的当前峰值 / 平均值（多数 IXP 只提供动态图非 API）
- M-Lab NDT 按年份、国家、ISP 的上 / 下行对称性官方汇总
- OpenAI / Anthropic / Google AI API 域名到 ASN 的连续采样
- 真实生产 LLM API input:output 字节或 usage token 跨用户数据集
