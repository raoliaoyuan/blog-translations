# H6 实验协议：验证 Anthropic prompt cache_read 字节削减

> 内部研究报告 · 实验协议 v0.1
>
> 假设来源：[Part 7.3 H6](../07-evidence/07-evidence.md)
>
> 实验目标：用 HTTP 字节级测量验证 Anthropic API 在 cache_read 场景下，**客户端→服务端 HTTP 请求体是否仍包含完整 prompt 内容**。

## 0. 问题重述

Part 5A 实测发现：96.1% 上行 **usage token** 计入 prompt cache_read。这一现象在 **token 计费层** 已确证；但在 **网络字节层** 的含义有两种可能：

| 情景 A | 情景 B |
|---|---|
| 客户端仍需提交完整 prompt 内容供服务端做 cache lookup | 客户端只需发送 cache key / 引用 |
| HTTP body 字节 ≈ cache_creation 时的字节 | HTTP body 字节 << cache_creation 时的字节 |
| **prompt caching 未削减上行字节** | **prompt caching 同时削减字节与计费** |
| 报告 5A.4 的现有论断成立 | 报告 5A.4 论断需撤回 |

本实验目的：通过对**同一段 prompt 在 cache_creation vs cache_read** 两种情景下的 HTTP 请求体字节数实测，区分情景 A vs B。

## 1. 实验设计

### 1.1 控制条件

- **prompt 内容**：使用约 5,000 token 的固定文本（足以触发 cache_control 标记）
- **API 端点**：Anthropic 官方 `/v1/messages`
- **客户端**：Python httpx 或 anthropic SDK，**禁用** SDK 内置缓存
- **网络**：本地 macOS / Linux，HTTPS 直连
- **模型**：Claude Opus 4.7 或 Sonnet 4.6（覆盖两个模型层级）

### 1.2 三组对照

| 组 | 描述 | 期望计费层行为 | 期望字节层行为（待实测） |
|---|---|---|---|
| **组 1** | 不启用 cache_control | 全部按 input_tokens 计费 | HTTP body ≈ N |
| **组 2** | 启用 cache_control，首次调用 | cache_creation_input_tokens | HTTP body ≈ N（情景 A/B 一致） |
| **组 3** | 启用 cache_control，5 分钟内再调用相同 prompt | cache_read_input_tokens | **情景 A：≈ N；情景 B：<< N** |

每组重复 5 次取平均，避免偶然误差。

### 1.3 测量方法

**方法 a：客户端层 instrumentation**

最简单。用 httpx 的 `event_hooks` 或 anthropic SDK 的 transport 自定义钩子，在发送前打印 `request.content` 长度。

```python
import httpx, anthropic, json

class ByteLogger(httpx.Client):
    def send(self, request, *args, **kwargs):
        body_bytes = len(request.content) if request.content else 0
        print(f"[REQ] {request.method} {request.url.path} body={body_bytes} bytes")
        resp = super().send(request, *args, **kwargs)
        return resp

client = anthropic.Anthropic(http_client=ByteLogger())
```

**方法 b：mitmproxy 抓包（TLS termination）**

更严格但需配置：

```bash
mitmproxy --mode regular --listen-port 8080
# Trust mitmproxy CA in macOS keychain
export HTTPS_PROXY=http://127.0.0.1:8080
export REQUESTS_CA_BUNDLE=~/.mitmproxy/mitmproxy-ca-cert.pem
python run_experiment.py
```

mitmproxy 会显示每个请求的完整字节数（含 TLS 框架开销可单独算）。

**方法 c：tcpdump 抓 TCP 流**

最底层但 TLS 后看不到内容，只能看总字节。适合验证"网络层真实字节"含 TLS overhead，但不能确认请求体内容。

**本协议推荐：方法 a + 方法 b 双账本对账**。

### 1.4 关键控制

- 必须在 cache TTL 内（5 分钟标准缓存 / 1 小时扩展缓存）做组 3 调用，否则 `cache_read` 不会触发
- 必须验证服务端返回的 `usage` 字段确实显示 `cache_read_input_tokens > 0`，否则该次调用无效
- 多次组 3 调用之间无其他差异，以排除版本切换、模型路由等噪声

## 2. 实验脚本

完整可执行脚本：[`h6-experiment.py`](h6-experiment.py)（与本协议同目录）

### 2.1 脚本骨架

```python
"""
H6 实验：测量 Anthropic API 在 cache_read 场景下的 HTTP 请求体字节数。
"""
import os
import json
import time
import httpx
import anthropic
from pathlib import Path

API_KEY = os.environ.get("ANTHROPIC_API_KEY")
if not API_KEY:
    raise SystemExit("ANTHROPIC_API_KEY 未设置")

# 5000 token 量级的固定 prompt（可换成读取本地长文档）
LONG_PROMPT_PATH = Path(__file__).parent / "h6-test-prompt.txt"
LONG_PROMPT = LONG_PROMPT_PATH.read_text() if LONG_PROMPT_PATH.exists() else "测试" * 2500

results = []

class ByteLogger(httpx.Client):
    last_request_body_bytes = 0
    def send(self, request, *args, **kwargs):
        ByteLogger.last_request_body_bytes = len(request.content) if request.content else 0
        return super().send(request, *args, **kwargs)

client = anthropic.Anthropic(api_key=API_KEY, http_client=ByteLogger())

def run_once(label, with_cache):
    messages = [{"role": "user", "content": [
        {"type": "text", "text": LONG_PROMPT, **({"cache_control": {"type": "ephemeral"}} if with_cache else {})}
    ]}]
    resp = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=128,
        messages=messages,
    )
    body_bytes = ByteLogger.last_request_body_bytes
    usage = resp.usage.model_dump() if hasattr(resp.usage, "model_dump") else dict(resp.usage)
    record = {
        "label": label,
        "with_cache": with_cache,
        "request_body_bytes": body_bytes,
        "input_tokens": usage.get("input_tokens", 0),
        "cache_creation_input_tokens": usage.get("cache_creation_input_tokens", 0),
        "cache_read_input_tokens": usage.get("cache_read_input_tokens", 0),
        "output_tokens": usage.get("output_tokens", 0),
    }
    results.append(record)
    print(json.dumps(record, ensure_ascii=False))

# 组 1：不启用 cache
for i in range(5):
    run_once(f"group1-no-cache-{i}", with_cache=False)
    time.sleep(0.5)

# 组 2 + 3：启用 cache，首次创建 + 多次命中
for i in range(5):
    run_once(f"group2-cache-creation-{i}", with_cache=True)
    time.sleep(0.5)
    run_once(f"group3-cache-read-{i}", with_cache=True)
    time.sleep(0.5)

with open("h6-results.jsonl", "w") as f:
    for r in results:
        f.write(json.dumps(r, ensure_ascii=False) + "\n")

# 分析
def avg(records, key):
    vals = [r[key] for r in records]
    return sum(vals) / len(vals) if vals else 0

group1 = [r for r in results if r["label"].startswith("group1")]
group2 = [r for r in results if r["label"].startswith("group2")]
group3 = [r for r in results if r["label"].startswith("group3")]

print(f"组 1 (no cache) avg body bytes: {avg(group1, 'request_body_bytes'):.0f}")
print(f"组 2 (cache creation) avg body bytes: {avg(group2, 'request_body_bytes'):.0f}")
print(f"组 3 (cache read) avg body bytes: {avg(group3, 'request_body_bytes'):.0f}")
print(f"组 3 / 组 2 字节比: {avg(group3, 'request_body_bytes') / avg(group2, 'request_body_bytes'):.4f}")
```

## 3. 结果判定

### 3.1 量化阈值

| 组 3 / 组 2 字节比 | 结论 |
|---|---|
| > 0.95 | **情景 A 确证**：cache_read 时 HTTP body 仍含完整 prompt → 报告"96% 重传"论断成立 |
| 0.05–0.95 | **混合 / 部分削减**：cache_read 削减一部分字节但不完全；需进一步拆解结构 |
| < 0.05 | **情景 B 确证**：cache_read 时 HTTP body 显著缩小到 cache key 量级 → 报告"96% 重传"论断撤回 |

### 3.2 三种结果对报告的影响

- **A**：5A.4、5A.3.2、Part 1.3.1、Part 6.2 的"prompt caching 未削减字节"论断升级 L1
- **B**：上述论断**撤回**，并修订为"prompt caching 同时削减字节与计费"
- **混合**：增加新 H 假设，按字节削减比例重新量化结论

## 4. 复现门槛

- **API key**：需 Anthropic Console 创建（成本约 $1–5 完成全部 30 次调用）
- **Python**：3.10+
- **依赖**：`pip install anthropic httpx`
- **网络**：无特殊要求；mitmproxy 路径可选
- **运行时**：约 5–10 分钟

## 5. 局限与扩展

- 本实验只覆盖 Anthropic。OpenAI 的 `previous_response_id`、Bedrock 的 prompt caching 实现等需平行实验。
- 仅覆盖 ephemeral（5 分钟）缓存；1 小时扩展缓存的行为可能不同。
- 仅覆盖文本 prompt；多模态（图像、PDF）的 cache_read 字节行为需补充。
- 不验证 SSE 下行字节细节；下行只看 output_tokens 即可。

## 6. 与本研究的关系

本协议是研究"诚实账本"的第二步：把"原本作为 L3 论断但被 Codex-B 审稿降为 L4 的字节判断"通过一次低成本实测升级为 L1，或反过来证伪并撤回。
