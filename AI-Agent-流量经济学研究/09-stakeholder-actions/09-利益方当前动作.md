[Part 1–8](../INDEX.md) 描述的是结构性问题与历史脉络。本部分把视角拉回最近 **12 个月**（2025-06 → 2026-06），看各利益方面对 AI Agent 流量冲击**实际采取了什么动作**——是调整价格？扩张带宽？修改协议？还是其他？

## 9.1 研究方法与范围

### 9.1.1 时间窗口

本部分只统计 **2025-06 至 2026-06** 的公开行动。早于此窗口的动作（如 EU Data Act 2024 立法、AWS 2024 egress 调整）已在 [Part 3](../03-cloud-pricing/03-公有云定价.md) 描述，本部分不重复。

### 9.1.3 关键发现（先抛结论）

**12 个月公开动作的共同特征**：**在公开层面，没有任何利益方推出名为"AI 流量费"的新计费项**（**注**：私有合约层动作不可见，本研究只覆盖公开信息），而是把压力分散到四层——

1. **容量价格层**：稀缺性体现为 GPU/TPU 容量预约价
2. **跨云私网层**：降低多云搬运摩擦
3. **协议降本层**：分两类——OpenAI 通过 `previous_response_id` / Responses API 实现**真正的字节削减**（服务端会话状态）；Anthropic prompt caching **降计费 + 服务端 prefill 优化**但**不削减客户端→服务端字节**（见 [H6 文献证据](../05-empirical/H6-文献证据.md)）
4. **底层路由层**：海缆 / IXP / 数据中心 / 监管安全边界下沉

**最少公开动作**：ISP / IXP 的"AI 专用对等"——目前仍是通用容量扩张。

**关键观察**：OpenAI **同时做两件事**——上游用 Stargate / Oracle 把推理容量从单一 Azure 约束中拆出来（资本密集型"容量护城河"），下游用 API 状态引用和缓存减少重复 token 与重复上下文传输（**协议层"流量压缩"**）。

> **这是本研究中唯一找到的"协议层字节削减"明确公开动作**——OpenAI 的 `previous_response_id` 让多轮 Agent 少传重复上下文。Anthropic prompt caching 是计费优化但不削减字节（见 [H6 文献证据](../05-empirical/H6-文献证据.md)）。

|---|---|---|
| 1 | OpenAI / Stargate | 容量护城河 + 协议层（Responses API） |
| 2 | Google / GCP | 监管合规 + 跨云 + 海缆 + TPU |
| 3 | Anthropic | 多云容量租赁 + 缓存（注：cache 不削减字节） |
| 4 | 美国 / EU 监管 | 海缆安全 + 切换约束 |
| 5 | AWS | GPU 涨价 + 跨云互联 |
| 6 | Azure / Microsoft | 海缆事件 + 被动响应 |
| 7 | 中国侧 | 算力网络规划，执行多为媒体报道（C 类） |
| 8 | IXP / ISP | 通用容量扩张为主；**DE-CIX AI-IX 是唯一显性 AI 专项 IXP 产品**；其他 IXP / ISP 未见公开 AI 专用对等 |

## 9.9 综合判断

### 9.9.1 压力分散到四层（关键论断）

12 个月内**在公开层面**没有任何利益方推出"AI 流量费"新计费项（私有合约不公开），但全部公开动作落到四层：

| 层 | 主导动作 | 代表案例 |
|---|---|---|
| **容量价格** | GPU/TPU 预约价上涨 + 长期合约锁定 | AWS ML Capacity Blocks 2026 H1 / 约 5 个月内复合涨 ~38%、OpenAI-Oracle $300B 五年 |
| **跨云私网** | 降低多云数据搬运摩擦 | AWS Interconnect-multicloud + Google Cloud CCI、GCP EU/UK Data Transfer Essentials |
| **协议降本** | OpenAI 用 Responses API state 削减字节；Anthropic prompt caching 降计费但不削减字节（见 [H6](../05-empirical/H6-文献证据.md)） | OpenAI `previous_response_id`、Anthropic cache_read 0.1× |
| **底层路由** | 海缆 / IXP / 数据中心 / 监管安全 | Google Blue-Raman 218 Tbps、Equinix Geo Zones、FCC 海缆许可 |

### 9.9.2 与 Part 1–8 结构性论断的对照

把动作密度与 [Part 8 结论](../08-conclusion/08-conclusion.md) 对照：

> Part 8 的结构性判断："**当前量级尚不足以独立触发结算重写；研究、监测和制度准备工作应当现在开始**"。
>
> Part 9 的动作密度判断：**基础设施准备活跃度高**——Stargate 三年 $400B、Anthropic 十年 $100B+（B 状态）、中国 2 万亿元算力网格规划（C 状态）。这种活跃度**与** Part 8 "长期跟踪指标" 建议的研究节奏在时间感觉上**不同步**。但是否由 AI Agent 流量驱动仍属推断（不下因果断言）。

这**可能**意味着市场参与者的**基础设施准备活跃度高于当前公开量级判断所对应的监测节奏**——他们在为未来某个时点的容量与流量约束做提前准备。**但需明示**：这是对动作密度的解读，不构成因果推断——投资强度也可能由 GPU 供应链、地缘竞争、监管不确定性等独立于 AI 流量结构的因素驱动，本研究**不下** "由 AI Agent 流量驱动" 的论断。

### 9.9.3 价格动作少于容量动作

12 个月内"价格调整"项的真实方向值得注意：

- **直接对零售客户涨价**：仅 AWS ML Capacity Blocks（且是 GPU 容量不是网络）
- **直接对零售客户降价 / 免费**：GCP EU/UK Data Transfer Essentials（窄场景）、Google Cloud 全球迁出免费（仅 Data Act 响应）
- **协议层降低有效成本**：OpenAI / Anthropic 缓存（减少计费 token，**不改变定价表**）
- **完全没有公开降价 / 涨价**：Azure 网络、所有 ISP / IXP

**核心信号**：公开价格表对 AI 流量基本不动；**所有动作集中在容量、协议、监管和底层路由**。

### 9.9.4 公开产品少于私有互联

显性观察的"公开产品创新"几乎为零（AI 流量专线、AI 对等产品都没有），但**私有 / 准私有互联线索密集**：

- 跨云 Cross-Cloud Interconnect（AWS-GCP）
- 推理服务商-云厂的多年算力合约
- 海缆联合体投资
- Equinix Geo Zones 这种"近私有"主权网络

**这与 [Part 2.1](../02-bgp-settlement/02-bgp-settlement.md#21-bgp-结算不是单一市场而是三层叠加) 论断方向一致**：BGP 结算的真实战场更可能在**设施层 + 容量层 + 私有互联**，而非路由层。但 Part 2.1 论断的最终确认仍需私有合约层的实测数据，本研究只能挂载公开线索作为弱证据。

### 9.9.5 ISP / IXP 在 AI 议题上的低公开动作密度（含一个例外）

8 类利益方中，ISP / IXP 整体动作密度仍排第 8，但**有一个重要例外**：**DE-CIX 已推出 AI-IX 产品**（[官网](https://www.de-cix.net/en/services/ai-ix)），这是本研究找到的**唯一**显性"AI 流量专用 IXP 产品"。其官方发布日期与具体技术规格本研究未挂载到精确日期，需进一步追踪。

除 DE-CIX 外，其他 IXP（AMS-IX、LINX、HKIX、Equinix）截至本研究检索日**未见公开 AI 专用对等产品**。可能解释：

1. **量级不足**：AI 流量在 IXP 公开统计中尚不可分辨（呼应 [Part 5B](../05-empirical/5B-公开观测.md) 论断）
2. **流量绕开**：hyperscaler 自有骨干 + 海缆把 AI 流量私有化，绕开公网 IXP
3. **谈判滞后**：欧盟公平贡献费仍在咨询，硬性网络费未落地
4. **观测局限**：DPI 厂商可能在内部已有动作但未公开

DE-CIX 的例外**表明 IXP 层面 AI 专项产品在 2025-2026 已经出现，但仍属个例**。这一发现修订了原稿"IXP 完全无 AI 专项"的强论断——更准确的判断是：**AI 专项 IXP 产品开始出现，但密度极低**。

### 9.9.6 中国侧延迟与差异

中国侧的动作集中在**国家级算力网络规划**（2 万亿元、2028 单一计算网格），但具体执行公告偏 C 类（媒体报道 / 推断）。与海外大幅不同：

- 海外：**企业 + 监管**双轨；资本市场 + 私有合约推动
- 中国：**国家级规划**主导；运营商作为执行方

**媒体报道层面呼应** [Part 4](../04-china-structure/04-中国结算结构.md) 论断：中国监管路径偏向"算力本地化（鼓励 / 引导）"——2 万亿元算力网格规划与这一路径方向一致，但因主要为媒体报道（C 类），**不能视为政策已"具体落地"的事实**。

## 9.10 待补与局限

- 私有合约层（云 ↔ 推理服务商、ISP ↔ CDN）大量动作不公开
- 部分公告状态难以从公开来源核实（A vs B vs C）；本研究尽量沿用 Codex-A5 标注，留以复核
- 中国侧公开度低于海外，C 类公告占比偏高
- 12 个月窗口可能遗漏长期战略性动作（如多年的海缆建设流程）
- 未覆盖**电力 / 冷却**等 AI 基础设施侧支撑动作（独立研究主题）

## 9.11 本部分小结

- **关键发现**：12 个月内**公开层面**没有任何利益方推出"AI 流量费"新计费项——公开动作分散到容量、跨云、协议、底层路由四层
- **动作密度排名**：OpenAI / Stargate > Google/GCP > Anthropic > 美国/EU 监管 > AWS > Azure > 中国侧 > IXP/ISP
- **市场行动密度高于 Part 8 客观量级判断**：资本市场和大客户在 2025-2026 已大举行动；但与流量结构的因果归因属推断（投资也可能受 GPU 供应、地缘竞争等因素驱动）
- **私有 / 准私有互联线索密集**：跨云 Cross-Cloud Interconnect、十年算力合约、海缆联合体、Geo Zones——与 [Part 2.1 三层叠加](../02-bgp-settlement/02-bgp-settlement.md#21-bgp-结算不是单一市场而是三层叠加) 论断方向一致
- **ISP / IXP 在 AI 议题上的低公开动作密度（含例外）**：DE-CIX AI-IX 是本研究找到的唯一显性 AI 专用 IXP 产品；其他 IXP / ISP 仍以通用容量扩张为主——可能是"承载者未感知"或"流量绕开公网"或"内部动作未公开"，无法定论
- **中国侧延迟与差异**：国家级算力网络规划主导，与海外企业 + 监管双轨不同
