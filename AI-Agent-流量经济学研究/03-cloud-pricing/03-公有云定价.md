# 第三部分　公有云出向定价：历史、现状与拐点

> 内部研究报告 · 草稿 v0.1 · 主要源材料：[Codex-A 资料笔记](codex-a-cloud-pricing-notes.md)
>
> 证据强度沿用 [Part 7.1 评级](../07-evidence/07-evidence.md#71-四级证据强度评级体系)。

如果说 [Part 2](../02-bgp-settlement/02-bgp-settlement.md) 描述的是互联网底座的物理与对等结算，那么本部分描述的是这一底座被**零售层包装**成"客户面"价目时的商业逻辑。公有云的"入向免费 + 出向阶梯收费"范式不是物理事实，而是一个 20 年前由 AWS 定下、被 GCP / Azure 几乎完全继承的商业选择。AI Agent 流量结构正在第一次让这个范式承压。

## 3.1 入向免费 + 出向阶梯收费的起源

### 3.1.1 AWS 早期范式

【L2】AWS S3 于 [2006-03-14 发布](https://press.aboutamazon.com/2006/3/amazon-web-services-launches-amazon-s3)。从发布日起，AWS 就把传统托管带宽包模式抛弃，改为"存储 + 请求 + 数据传输"三项独立按量计费。这是云计算商业模型的关键转折点——把网络从机柜租赁拆分到"按 GB 计费"的零售商品。

【L2】学术早期评估见 [Garfinkel Harvard TR-08-07](https://dash.harvard.edu/bitstream/handle/1/24829568/tr-08-07.pdf?sequence=1)，记录了 2006–2007 年 AWS 的"低固定成本 + 用量计费"模型，是补 2006–2009 定价档案的重要入口。

【L4 考古入口】最早的具体"入向免费"政策定型时间需从 Wayback 抓取：
- [S3 Wayback index](https://web.archive.org/web/*/http://aws.amazon.com/s3*)
- [EC2 Wayback index](https://web.archive.org/web/*/http://aws.amazon.com/ec2*)

候选证据：[2009-03-31 AWS blog "Celebrating S3's Third Birthday With Special Anniversary Pricing"](https://aws.amazon.com/blogs/aws/celebrating-s3s-third-birthday-with-special-anniversary-pricing/)，需复核是临时促销还是长期规则。**仍缺数据**：精确的"入向免费成为永久政策"时间点。

### 3.1.2 现行成熟形态

【L2】[AWS EC2 价目页](https://aws.amazon.com/ec2/pricing/on-demand/) + [S3 价目页](https://aws.amazon.com/s3/pricing/) 当前明文：

- 互联网入向**免费**
- 互联网出向**前 100 GB / 月免费**（跨多项 AWS 服务和区域汇总）
- 超过额度后按阶梯计费
- **中国区与 GovCloud 例外**
- 超过 500 TB/月需联系销售（自定义合约）

【L3 推断】GCP / Azure **基本继承**这一经济结构但不完全复制：

- GCP 区分 [Premium / Standard Network Service Tiers](https://cloud.google.com/vpc/network-pricing)：Premium 走 Google 全球骨干，价格高；Standard 走公网 transit，价格低
- Azure 区分 [Microsoft Premium Global Network 与 Routing Preference transit ISP](https://azure.microsoft.com/en-us/pricing/details/bandwidth/)：前者走微软骨干，后者走标准 transit

这种分层的本质是把 [Part 2.4](../02-bgp-settlement/02-bgp-settlement.md#24-互联设施与容量批发) 描述的"自有骨干 vs 买 transit"差异透传到客户面。

## 3.2 海外三巨头当前公开价目

### 3.2.1 AWS

【L2】[AWS EC2 pricing](https://aws.amazon.com/ec2/pricing/on-demand/)、[EC2 FAQ](https://aws.amazon.com/ec2/faqs/) 当前明文：
- 入向免费
- 出向前 100 GB/月免费
- 超过 500 TB/月需谈合约
- EU 客户可按 Data Act 申请降低特定用例费率
- 搬离 AWS 时可申请**免费互联网出向信用**（Data Act 响应）

【L4 仍缺数据】AWS S3 美国西部出向 **$0.09/GB** 是常见公开对比基线（[Backblaze 对比页](https://www.backblaze.com/cloud-storage/pricing) 引用），但本研究未抓到 AWS 静态表格作为权威源，需用 AWS Price List API 复核。

### 3.2.2 GCP

【L2】[GCP network pricing](https://cloud.google.com/vpc/network-pricing) 当前明文（Premium Tier 到北美/欧洲/多数亚洲目的地）：

| 阶梯 | 单价 |
|---|---|
| 前 1 GiB/月 | 免费 |
| 1 GiB – 1 TiB | $0.12/GiB |
| 1 TiB – 10 TiB | $0.11/GiB |
| 10 TiB 以上（北美） | $0.08/GiB |
| 10 TiB 以上（欧洲/多数亚洲） | $0.085/GiB |
| **中国目的地首档** | **$0.23/GiB** |

【L2】页面注明 **2024-02-01 起部分 Premium Tier 互联网出向 SKU 涨价**——这是难得的"公有云出向涨价"公开证据。

### 3.2.3 Azure

【L2】[Azure bandwidth pricing](https://azure.microsoft.com/en-us/pricing/details/bandwidth/) 当前明文：
- Data Transfer In 免费
- Premium Global Network 互联网出向前 100 GB/月免费
- 北美/欧洲到任意目的地下一级 10 TB：$0.087/GB
- 之后阶梯：$0.083 → $0.07 → $0.05
- Routing Preference transit ISP 更低（北美/欧洲下一 10 TB 为 $0.08/GB）

### 3.2.4 历史调价时间线

【L4 仍缺数据】AWS 2017、2020 互联网出向重大调价的官方公告 URL 本轮未稳定找到。建议下一轮按 "AWS price reduction data transfer out 2017 2020" 与 AWS Price List API 历史快照补证。GCP / Azure 同期调价完整时间线同样缺失。

**目前可建立的时间线锚点**：
- 2006-03-14：AWS S3 发布，按 GB 计费模式确立
- 2009-03-31（候选）：AWS 入向免费政策可能定型
- 2024-02-01：GCP Premium Tier 部分 SKU 涨价
- 2024-01-12：GCP 宣布免费迁出（Data Act 响应）
- 2024-2025：AWS / Azure 跟进 Data Act 类似策略

## 3.3 EU Data Act 与 egress fee 下调

### 3.3.1 法律基础

【L2】[Regulation (EU) 2023/2854](https://data.europa.eu/eli/reg/2023/2854/oj) 把概念明确：

- **Data egress charges**：客户把数据从云商 ICT 基础设施经网络取出到另一云或本地时的数据传输费
- **Switching charges**：包含 data egress charges 在内的"切换成本"
- **Recital 88**：明示过高 egress fee 抑制迁移、限制数据自由流动、造成锁定
- **规则**：switching charges 在法规生效**三年后禁止收取**；过渡期内只能降低收取
- **关键日期**：**2024-01-11 生效**、**2025-09-12 多数条款开始适用**、**2027-01-12 起禁止收取 switching charges**

这是世界范围内第一次把"出向带宽费"作为**市场竞争与锁定（lock-in）议题**写入正式法规。原稿"反垄断议题"措辞已撤回——Data Act 不是反垄断法（EU 反垄断走 Article 101/102），而是关于公平数据访问、互操作性与可切换性的横向数据法规。

### 3.3.2 三家响应路径

【L2】

- **Google**：[2024-01-12 宣布](https://cloud.google.com/blog/products/networking/eliminating-data-transfer-fees-when-migrating-off-google-cloud) "停止使用 Google Cloud 并迁往其他云或本地的客户可免费网络数据转出"，**全球适用**。退出页要求提交 Exit Notice，最终发票给出数据转移成本信用。[Exit page](https://cloud.google.com/exit-cloud)
- **AWS**：[EC2 FAQ](https://aws.amazon.com/ec2/faqs/) 要求客户在搬离前**联系 Support 申请**"free data transfer to move off AWS"；批准后给临时信用，通常 90 天内完成迁出
- **Azure**：[价目 FAQ](https://azure.microsoft.com/en-us/pricing/details/bandwidth/) 称客户为切换到另一云或本地数据中心而离开 Azure 时可**申请**超过每月 100 GB 免费额度的出向信用

【L3 行业共识】三家的响应路径都是"信用 / 申请 / 批准"，**不等于全量客户自动降价**。这意味着 Data Act 对日常使用的客户没有直接价目影响，仅在迁云时触发。

### 3.3.3 单独看 Google 的 Data Transfer Essentials

【L2】Google 另推出 [Data Transfer Essentials](https://docs.cloud.google.com/data-transfer-essentials/docs/overview)，用于同一组织跨云平台的服务间公网传输；文档称初期按指引使用不收费，若未来收费会提前通知。这是"非迁云场景下的免费跨云"创新，但范围有限。

【L4 仍缺数据】没有找到可引用的真实客户账单前后对比来量化 Data Act 影响。

## 3.4 零出向挑战者

### 3.4.1 三家代表

【L2】

- **Cloudflare R2**（[官方价目](https://developers.cloudflare.com/r2/pricing/)）：
  - Standard 存储 $0.015/GB-month
  - Class A 操作 $4.50/百万次
  - Class B 操作 $0.36/百万次
  - **所有存储类直接出向到互联网免费**
  - 免费层含 10 GB-month、100 万 Class A、1000 万 Class B
- **Backblaze B2**（[官方价目](https://www.backblaze.com/cloud-storage/pricing)）：
  - 起价 $6.95/TB/月
  - **免费出向最高为平均月存储量 3 倍**，超过后 $0.01/GB
  - B2 Overdrive 标注 unlimited free egress
- **Wasabi**（[官方价目](https://wasabi.com/pricing/)）：
  - Pay-as-you-go 起价 $6.99/TB/月，**2026-07-01 调至 $7.99/TB/月**
  - 页面明确无 egress 或 API 请求费

### 3.4.2 市场份额

【L3 行业共识 / 仍缺数据】对象存储挑战者用"零出向"攻击 hyperscaler 定价，但公开市场份额通常只统计整体 IaaS/PaaS 云：

- Synergy Q1 2025：AWS 32%、Azure 23%、GCP 10%（[TechRadar 引用](https://www.techradar.com/pro/google-slashes-uk-and-eu-cloud-data-transfer-fees-ahead-of-eu-data-act)）
- Cloudflare R2 / Backblaze / Wasabi 的**对象存储收入份额未见可审计公开口径**

### 3.4.3 挑战者对范式的影响

【L3 行业共识】挑战者通过"零出向"建立的存在，是对 hyperscaler 定价范式的市场化挑战。挑战者长期存活并扩张，**支持"hyperscaler 出向收费包含商业溢价"的可能性**——但**不能直接证明溢价比例**：挑战者可能在存储单价、API 次数、可用性、跨区等其他维度收回成本。这一论断只能作为行业共识引用，不能定量化。

## 3.5 中国公有云出向定价

### 3.5.1 三大云的现行模式

【L2】

- **腾讯云**（[公网网络计费文档](https://intl.cloud.tencent.com/document/product/213/10578)）：
  - 多线 BGP ISP 接入
  - 按带宽计费（按传输速率）+ 按流量计费（按公网出方向流量逐小时）
- **阿里云**（[ECS/EIP 公网带宽文档](https://help.aliyun.com/zh/ecs/user-guide/public-bandwidth)）：
  - 按固定带宽 / 按使用流量两种
  - 实际 RMB 单价随地域、线路、EIP/CLB/CDT 等产品变化（**Codex-A2 待补**：抓阿里云价格计算器或中国站区域价格页的最新单价）
- **华为云**（[EIP 价目文档](https://support.huaweicloud.com/intl/en-us/price-eip/eip_price_0001.html)）：
  - 按需计费分按带宽 / 按流量
  - 线路区分全动态 BGP / 静态 BGP 等

### 3.5.2 多线分层的本质

【L4 推断】中国云的"优质 BGP / BGP Pro / 三网通 / 多线 BGP"分层不是简单的"互联网出向 GB 价"差异——而是**对跨运营商路由质量与覆盖的分层定价**。同一云商在 ECS、EIP、CDN、全球加速、云数据传输等产品下给出不同带宽 / 流量口径。**这种分层是 [Part 4.3 中国结算结构](../04-china-structure/04-中国结算结构.md#43-公有云与运营商的结算模式) 描述的"运营商互联 + 跨网 BGP"成本透传**。

### 3.5.3 入向同样免费

中国三大公有云的入向带宽**与海外一致：免费**。这意味着 AI Agent 客户在国内云上的入向激增也不被计费——但云厂的采购成本（多线 BGP 带宽）按总流量计，本质上是被吞噬利润。这是 Part 1 中描述的"入向免费假设"在中国语境下的同步承压。

## 3.6 出向带宽真实毛利率

### 3.6.1 学术与行业引用

【L2】

- [arXiv 2104.06913](https://arxiv.org/abs/2104.06913)：高能物理云突发实验论文指出，对数据密集型应用，**egress networking costs can exceed compute costs**。讨论用 Internet2 Cloud Connect 等专线降低三大云出向费用。
- [arXiv 2203.06725](https://arxiv.org/abs/2203.06725)：网络带宽分配论文从云提供商角度称带宽成本是 operating cost 的 major component，但只研究优化问题，不披露 hyperscaler COGS。

### 3.6.2 行业共识

【L3】[a16z《The Cost of Cloud: A Trillion Dollar Paradox》](https://a16z.com/the-cost-of-cloud-a-trillion-dollar-paradox/) 把云账单视为可观的软件毛利压力，但重点是整体云成本与 repatriation，**并非 egress 毛利拆解**。

### 3.6.3 仍缺数据

【L4 仍缺数据】未找到 AWS / Azure / GCP 披露"互联网出向"单项毛利率或网络成本结构。**可比较的是**：零售 egress 价（$0.05–0.12/GB 量级）与批发 IP transit / peering 成本（[Part 2.6 TeleGeography](../02-bgp-settlement/02-bgp-settlement.md#26-telegeography-ip-transit-价格史) 报告趋势性下降，但本研究**未挂载具体 $/Mbps·月数值**——TeleGeography 报告为付费产品）之间存在**数量级差**。但这只是数量级差，**不能直接换算为毛利率**，因为存在客户分摊的接入设备、跨区光缆、冗余、技术支持等共同成本。

## 3.7 历史争议：出向费是不是利润中心

【L3 行业共识】"出向带宽是 hyperscaler 利润中心"主要来自三类来源：

1. **挑战者宣传**：Cloudflare、Backblaze、Wasabi 公开对比页（[R2](https://developers.cloudflare.com/r2/pricing/)、[Backblaze](https://www.backblaze.com/cloud-storage/pricing)）反复强调"零出向"是更公平的定价
2. **开发者账单争议**：社区中关于"被 egress 吃掉的预算"的讨论广泛存在
3. **监管评论**：EU Data Act 的 Recital 88 明确认为"过高或不合理的出向 / 迁移费用"形成锁定、限制竞争——这是**最强的监管层证据**，虽未直接说"利润中心"，但暗示了"超出成本的溢价"

可信度评估：**中等**。零售价格长期稳定（基线 $0.05–0.12/GB 量级 20 年几乎不变），挑战者可做到零 / 低出向；但缺少 hyperscaler 分项成本审计。

【L4 仍缺数据】CNCF / FinOps Foundation 对 egress fee 毛利率的正式量化立场本轮未找到。可继续检索 FinOps 关于 data transfer cost allocation / FOCUS 的材料。

## 3.8 拐点观察：入向是否仍能维持免费？

【L4 推断，开放问题】把本部分（公有云零售）与 Part 2（互联底座）+ Part 5A（实测）+ Part 6（影响）综合看，"入向免费"范式承受的压力来自三个方向：

1. **客户使用结构变化**：AI Agent 客户的真实流量结构反转下行驱动假设（Part 5A 实测支持）
2. **挑战者市场存在**：零出向云商提供反证（3.4 节）
3. **监管压力**：Data Act 已开局（3.3 节）

但**承受压力 ≠ 必然反转**。三家 hyperscaler 当前的应对策略是：
- 维持入向免费
- 在出向侧通过 Data Act 响应（信用 / 申请制）做最小让步
- 对挑战者保持沉默或差异化竞争

**判定**：入向免费在可见的未来（数年）**很可能仍能维持**。真正的拐点不会出现在常规客户面，而是出现在**少数超大客户（推理服务商）的合约层面**——但这部分内容**不公开**，本研究无法量化。

## 3.9 本部分小结

- AWS 在 2006 年定下的"入向免费 + 出向阶梯"范式，被 GCP / Azure 几乎完全继承
- 三家当前出向价目（[AWS](https://aws.amazon.com/ec2/pricing/on-demand/) / [GCP](https://cloud.google.com/vpc/network-pricing) / [Azure](https://azure.microsoft.com/en-us/pricing/details/bandwidth/)）的首档基线在 $0.05–0.12/GB 量级，长期稳定
- EU Data Act 是**首次以法律形式对 egress fee 施加监管压力**，三家以"迁云信用"做有限响应，对日常客户无直接影响
- 零出向挑战者（R2 / B2 / Wasabi）通过市场化反证暗示 hyperscaler 出向定价含商业溢价，但缺审计证据
- 中国云在**入向免费**这点与海外完全一致；出向计费在结构上类似（按带宽 / 按流量），但具体单价、阶梯、线路（全动态 BGP / 静态 BGP / 三网通）模式更分散，需中国站价目页逐项复核（Codex-A2 待补）。多线 BGP 分层与跨境产品有额外定价层级。
- 出向毛利率**没有公开审计数据**，行业共识"是利润中心"可信度中等
- 入向免费在常规客户面**可能仍能维持数年**；真正拐点在超大推理服务商合约层（不公开）
